**Step 6 — Verify same filesystem (critical for hardlinks):**

```bash
ssh root@192.168.10.199 "docker exec prowlarr-llm-proxy python3 -c \"
from pathlib import Path
dl = Path('/data/torrents')
tv = Path('/data/media/tv')
mv = Path('/data/media/movies')
print(f'downloads: dev={dl.stat().st_dev}')
print(f'tv:        dev={tv.stat().st_dev}')
print(f'movies:    dev={mv.stat().st_dev}')
assert dl.stat().st_dev == tv.stat().st_dev == mv.stat().st_dev, 'CROSS-DEVICE ERROR!'
print('OK: all paths on same device')
\""
```

This MUST print "OK". If it shows CROSS-DEVICE ERROR, STOP and investigate the volume mount configuration. This is a BLOCKING issue -- do not proceed.

**Step 7 — Verify USE_NEW_HANDLER is active:**

```bash
ssh root@192.168.10.199 "docker exec prowlarr-llm-proxy env | grep -E 'USE_NEW_HANDLER|DOWNLOAD_PATH|SONARR_LIBRARY|RADARR_LIBRARY'"
```

Should show all four variables with correct values.

**Troubleshooting checklist if anything fails:**

1. Container not running? → `docker logs prowlarr-llm-proxy` for startup errors
2. Health endpoint fails? → Check port bindings: `docker port prowlarr-llm-proxy`
3. Volume not mounted? → Re-run deploy.sh, verify `-v` flag is in script
4. Paths don't exist inside container? → Wrong volume mount source; check host paths from Task 1 discovery
5. Cross-device error? → Separate volume mounts detected; ensure single parent mount
6. Path validation error on startup? → Create missing directories on host: `mkdir -p /mnt/user/data/media/{tv,movies}`
7. Redis/qBit connection errors in logs? → Check that existing NAS .env credentials weren't overwritten
