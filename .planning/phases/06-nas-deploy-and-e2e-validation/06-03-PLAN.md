<objective>
Close the two major UAT gaps that prevent Sonarr/Radarr from auto-importing hardlinks.

Gap 1 (test 6): Sonarr/Radarr auto-import fails because the hardlink subfolder is named after the
sanitized series/movie title, but Sonarr sends qBittorrent's content_path (torrent.name) to the
Remote Path Mapping lookup. Fix: use torrent.name (sanitized) as the staging subfolder everywhere.

Gap 2 (test 7): Subtitle hardlinks are missing because (a) _process_subtitles is only called after
the polling loop exits — never runs for in-progress downloads, and (b) multiple subtitle groups
whose files share the same bare filename all collapse to the same destination path (last-write-wins).
Fix: process subtitles inside the polling loop alongside videos, and use the full torrent-relative
path to build disambiguated destination paths.

Purpose: Both fixes are required before Sonarr/Radarr can cleanly import downloaded content.
Output: Updated media_handler.py; llm.py subtitle mapping key handling confirmed correct (no change needed).
</objective>

Two bugs to fix in subtitle handling. Both are in media_handler.py:

**Bug A — Subtitles only after 100% complete:**
Currently `_process_subtitles` is called at lines 244-252 AFTER the polling loop exits. This means
for in-progress downloads, subtitles are never created.

Fix: Move subtitle processing INSIDE the polling loop, parallel to the TV video hardlink block.
After `all_video_mappings.update(batch_mappings)` in the TV branch (around line 201), add a call to
a subtitle processing helper. Track which subtitle files have already been hardlinked in a
`hardlinked_subs: set[str]` (parallel to `hardlinked` for videos). Initialize it before the loop.

Rename `_process_subtitles` to `_process_subtitles_incremental` and add:
- `torrent_name: str` parameter (replaces `series_title`)
- `already_hardlinked_subs: set[str]` parameter — skip sub_name entries already in this set;
  add newly hardlinked subs to it after processing (mutate in place)

The incremental call inside the TV branch of the polling loop:
```python
await self._process_subtitles_incremental(
    download_id=download_id,
    save_path=save_path,
    video_mappings=all_video_mappings,
    torrent_name=torrent_name,
    hardlink_base=hardlink_base,
    already_hardlinked_subs=hardlinked_subs,
)
```

Remove the post-loop call to `_process_subtitles` at lines 244-252.

**Bug B — Subtitle group collision (identical bare filenames):**
Currently at line 473: `sub_basename = Path(sub_name).name` strips the group folder prefix,
collapsing all groups to the same bare filename. Then line 474 looks up
`subtitle_mappings.get(sub_basename, sub_basename)` using a bare key, but `llm.py` stores mappings
keyed by full torrent-relative path (e.g. `Cqur Far/01.ass`). The bare key never matches, and all
groups write to the same destination path.

Fix the destination path construction inside `_process_subtitles_incremental`:
```python
for sub_name in subtitle_names:
    if sub_name in already_hardlinked_subs:
        continue
    src = save_path / sub_name
    if src.exists():
        # Use LLM mapping (full path key) or fall back to preserving group dir + filename
        new_name = subtitle_mappings.get(sub_name, None)
        if new_name:
            # LLM gave a flat name like "Show.S01E01.rus.SovetRomantica.ass"
            dst = hardlink_base / safe_torrent / new_name
        else:
            # No LLM mapping: preserve group directory for disambiguation
            # e.g. sub_name = "Cqur Far/01.ass" -> dst = hardlinks/{torrent}/Cqur Far/01.ass
            dst = hardlink_base / safe_torrent / sub_name
        subtitle_pairs.append((src, dst))
```

After calling `self._hardlink_service.create_hardlinks(subtitle_pairs)`, add each successfully
hardlinked sub_name to `already_hardlinked_subs` so it is skipped on future polling iterations.

Key changes:
- `subtitle_mappings.get(sub_name, ...)` uses full torrent-relative path (matches llm.py key)
- Fallback preserves the group directory (`sub_name` contains the folder prefix) instead of
  stripping it — so three groups with `01.ass` land in different subdirs
- `safe_torrent` derived from `torrent_name` parameter (from Task 1 fix)
  </action>
