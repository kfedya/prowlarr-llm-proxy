Create `app/services/media_handler.py` with:

```python
class MediaHandlerService:
    """Thin orchestrator that replaces SonarrHandlerService.

    Flow: webhook -> lookup mapping -> poll qBit for metadata -> verify files on disk
    -> compute hardlink pairs -> create hardlinks -> process subtitles.

    No qBittorrent rename API calls. No rescan trigger (files fill in-place).
    """
```

**Constructor parameters:**
- `torrent_mapping_service: TorrentMappingService`
- `qbittorrent_service: QBittorrentService`
- `hardlink_service: HardlinkService`
- `subtitle_service: SubtitleService`
- `llm_service: LLMService | None = None`
- `download_path: Path` (from config)
- `hardlink_base: Path` (from config, e.g., `/downloads/hardlinks`)

All type imports under `TYPE_CHECKING` to avoid circular imports. Use `structlog.get_logger(__name__)`.

**Method: `async def handle_grab_event(...)`**
Parameters: `release_title: str`, `download_id: str`, `media_type: MediaType`, `series_title: str | None = None`, `movie_title: str | None = None`, `season_number: int | None = None`, `episode_numbers: list[int] | None = None`

Flow:
1. Look up torrent mapping: `await self._mapping_service.get_by_title(release_title)`. If not found, log warning and return.
2. Poll for torrent + files on disk: `await self._poll_for_files_on_disk(download_id, mapping.original_title)`. If timeout, log error and return.
3. Compute hardlink (src, dst) pairs using `_compute_hardlink_pairs()`.
4. Call `self._hardlink_service.create_hardlinks(pairs)`. If `result.errors`, log error and abort (per user decision: no fallback).
5. Process subtitles: get file list from qBit, filter subtitles via `self._subtitle_service.filter_subtitle_files()`, match via `self._subtitle_service.match_subtitles_to_videos()`, create hardlink pairs for subtitles, call `create_hardlinks()` for subtitle pairs.
6. Log completion summary.

Wrap entire flow in try/except, log errors.

**Method: `async def _poll_for_files_on_disk(...)`**
Implements fast-then-backoff polling per user decision:
- `FAST_INTERVAL = 2.0`, `SLOW_INTERVAL = 10.0`, `FAST_CUTOFF = 30.0`, `MAX_TIMEOUT = 600.0`, `RETRY_DELAY = 300.0`
- 2 attempts (retry once after 5-min delay)
- Each attempt: poll qBit API for torrent info (skip if state == "metaDL"), get file list, check if files exist on disk at `save_path / file.name` using `Path.exists()`
- Use `async with self._qb_service:` once per poll iteration (login/logout per check)
- On timeout after both attempts, raise `TimeoutError` or return empty list

Per research pitfall #4: use `save_path / f.name` since qBittorrent file names include the torrent folder prefix for multi-file torrents.

**Method: `_compute_hardlink_pairs(...)`**
Static or instance method. Parameters: `files: list[Path]` (existing file paths on disk), `hardlink_base: Path`, `subfolder_name: str`.
For each file, compute `dst = hardlink_base / subfolder_name / file.name` (just the filename, strip directory prefix).
Return `list[tuple[Path, Path]]`.

**Method: `_make_subfolder_name(...)`**
Static method. Parameters: `media_type: MediaType`, `title: str`, `season_number: int | None`, `episode_numbers: list[int] | None`, `year: int | None = None`.
Returns sanitized subfolder name. Format per research:
- TV: "Title - S01E05" or "Title - S01E01-E12" or "Title - S01"
- Movie: "Title (Year)" or just "Title"
Sanitize `/` and `\` to `-`.

**IMPORTANT constraints from user decisions:**
- No rescan trigger (WHOK-06 deferred). Do NOT call Sonarr RescanSeries API. Comment in code: "Rescan deferred per user decision -- hardlinks fill in-place."
- Hardlink failure: log error and abort. No copy fallback.
- qBittorrent API errors during polling count toward the 10-minute timeout.

Add hardlink_service provider. Note: HardlinkService requires `download_path` and `library_paths` at construction time and validates same-device. For dev/CI where paths don't exist, wrap in a factory or use a `providers.Factory` that's only resolved when `use_new_handler=True`. Simplest approach: use `providers.Singleton` with a callable factory function:

```python
def _create_hardlink_service(settings: Settings) -> HardlinkService | None:
    """Create HardlinkService only if new handler is enabled and paths exist."""
    if not settings.use_new_handler:
        return None
    library_paths = []
    if settings.sonarr_library_path:
        library_paths.append(settings.sonarr_library_path)
    if settings.radarr_library_path:
        library_paths.append(settings.radarr_library_path)
    hardlink_base = settings.hardlink_path or (settings.download_path / "hardlinks")
    # HardlinkService validates same-device for library_paths, but hardlink_base
    # is under download_path so it's on the same device by construction.
    # We pass [hardlink_base] as library_paths since hardlinks go there.
    return HardlinkService(
        download_path=settings.download_path,
        library_paths=[hardlink_base] + library_paths if library_paths else [hardlink_base],
    )
```

Actually, reconsider: the hardlinks go from `download_path/{torrent}/file` to `hardlink_base/{subfolder}/file`. Both are under `download_path`, so same device is guaranteed. The `library_paths` parameter in HardlinkService is for cross-device validation. Since hardlink_base is under download_path, validation will pass. But we still need to validate vs Sonarr/Radarr library paths? No -- per user decision, hardlinks go to `downloads/hardlinks/`, NOT to the Sonarr/Radarr library. Sonarr/Radarr are configured externally to look at the hardlinks directory.

So: `HardlinkService(download_path=settings.download_path, library_paths=[hardlink_base])`.

Add provider:
```python
hardlink_service = providers.Singleton(
    _create_hardlink_service,
    settings=config,
)
```
